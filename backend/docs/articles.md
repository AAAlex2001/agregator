# Статьи-новости: формат, требования, загрузка

Новости раздела `/news` хранятся в репозитории как JSON-файлы `backend/content/articles/<slug>.json`,
обложки — `backend/content/articles/covers/<slug>.webp`. Скрипт импорта загружает их в таблицу
`articles` (kind NEWS, status PUBLISHED). Фронт читает статьи только через API бэкенда.

```
python -m scripts.validate_articles            проверить все статьи
python -m scripts.validate_articles <slug>...  проверить выбранные
python -m scripts.import_articles              загрузить в БД (обновление по slug)
```

## Файл статьи

```json
{
  "slug": "proektirovanie-pod-klyuch-chto-vhodit-v-uslugu",
  "legacy_id": -999,
  "direction": "DESIGN",
  "format": "guide",
  "title": "Проектирование под ключ: что входит в услугу и что остаётся за скобками",
  "excerpt": "2–3 предложения лида: о чём статья и что читатель получит.",
  "tags": ["Проектирование", "Выбор подрядчика", "Договор"],
  "meta_title": "Проектирование под ключ: что входит в услугу",
  "meta_description": "Описание для поисковой выдачи, 90–200 символов.",
  "meta_keywords": "проектирование под ключ, что входит в проектирование под ключ, ...",
  "published_at": "2026-08-15T09:00:00Z",
  "content_html": "<p>...</p> <h2>...</h2> ..."
}
```

| Поле | Правило |
| --- | --- |
| `slug` | совпадает с именем файла; латиница, цифры, дефисы. Не меняется — это URL `/news/<slug>` |
| `legacy_id` | отрицательный id статьи из старого фронта (для переноса лайков и просмотров); у новых статей `null` |
| `direction` | `EXPERTISE`, `AUDIT_SUPB`, `TECH_DIAG`, `DESIGN`, `SURVEY`, `ECOLOGY`, `RESEARCH`, `CADASTRAL`, `FORENSIC` или `null` для общих новостей отрасли |
| `format` | `guide`, `faq`, `howto`, `checklist`, `compare`, `price`, `news` |
| `title` | 30–120 символов, это H1 страницы |
| `excerpt` | 100–400 символов, лид под заголовком и текст карточки |
| `tags` | 1–5 тегов, первый — тема направления |
| `meta_title` | 20–80 символов |
| `meta_description` | 90–200 символов |
| `meta_keywords` | 5–10 поисковых фраз через запятую |
| `published_at` | ISO 8601 с `Z`; у перенесённых статей не меняется |
| `content_html` | тело статьи, требования ниже |

## Тело статьи

Объём — 900–1800 слов (цель 1000–1400). Структура:

1. Вступление — 1–3 абзаца `<p>` до первого `<h2>`: проблема читателя и что он узнает.
2. 5–10 разделов `<h2>`. Внутри — абзацы, списки, при необходимости `<h3>`.
3. Минимум одна таблица `<table>` с `<thead>` и `<tbody>`, 2–5 колонок, от 3 строк.
   Первая колонка — подпись строки. Таблица должна нести смысл: сравнение вариантов,
   сроки и документы, обязанности сторон, штрафы, состав работ, признаки и последствия.
4. Минимум два списка `<ul>`/`<ol>`. Ключевая мысль пункта — в `<strong>` в начале.
5. Последний `<h2>` — практический: «С чего начать», «Что проверить до…», «Как не…».
6. Финальный абзац — призыв к действию на «Ресурс-Плюс» со ссылкой на страницу направления.
7. Ссылки на нормы — прямо в тексте, `<a href='…' target='_blank' rel='noopener noreferrer'>`.

Требования по формату:

| `format` | Обязательно |
| --- | --- |
| `faq` | не меньше 4 заголовков `<h2>`, заканчивающихся на «?» (из них собирается разметка FAQPage) |
| `howto` | нумерованный список шагов `<ol>` не короче 5 пунктов |
| `checklist` | не меньше 3 списков; разделы вида «Блок 1. …» |
| `compare` | таблица сравнения минимум с 3 колонками |
| `price` | таблица факторов стоимости; без выдуманных цен |
| `guide`, `news` | общие требования |

Разрешённые теги: `p h2 h3 ul ol li strong em a blockquote table thead tbody tr th td br`.
Атрибуты: `href`, `target`, `rel` у ссылок, `colspan`/`rowspan` у ячеек, `start` у `ol`.
Запрещены `h1`, `img`, `class`, `style`, скрипты.

Внутренние ссылки — только на страницы платформы:
`/`, `/news`, `/rtn`, `/ekspertiza-promyshlennoy-bezopasnosti`, `/audit-supb`,
`/tehnicheskoe-diagnostirovanie`, `/proektirovanie`, `/inzhenernye-izyskaniya`, `/ekologiya`,
`/nir`, `/kadastrovye-raboty`, `/sudebnaya-ekspertiza`.

Внешние ссылки — только из каталога `backend/content/links.json` (адрес → официальное
название документа или страницы). Каждый адрес в каталоге открыт и сверен с названием вручную
или агентом-проверяющим; валидатор отклоняет любую внешнюю ссылку вне каталога. Новый адрес
сначала проверяется и добавляется в каталог, потом используется в статье. Подпись ссылки
должна соответствовать названию из каталога.

## Редакционные правила

- «Ресурс-Плюс» — площадка-агрегатор: заказчик бесплатно размещает заявку, исполнители
  (эксперты, лаборатории, проектировщики, изыскатели, экологи, кадастровые инженеры, судебные эксперты)
  откликаются с ценой и сроками, договор заключается напрямую, без комиссии. Площадка сама
  работы не выполняет — так и пишем в призыве к действию.
- Факты не выдумываются: номера статей, суммы штрафов, сроки и цены — только достоверные.
  Если точной цифры нет — формулировка без цифры.
- Без воды и канцелярита, без обращений к конкурентам, без «в данной статье».
- Под статьёй страница сама выводит форму заявки, в середине — виджет направлений.
  Писать «опишите задачу в форме ниже» можно.

## Статьи о тендерных площадках

Серия о закупках услуг и тендерных площадках помечается первым тегом «Тендерные площадки».
Сравнение с другими площадками — только по проверяемым критериям: модель оплаты, кто
участвует, проверка аттестации, прямой контакт с заказчиком, отбор не только по цене,
порог входа. Без принижения конкурентов и без ссылок на их сайты: нормы — на consultant.ru,
ЕИС — zakupki.gov.ru, ФАС — fas.gov.ru. Формулировки должны выдерживать ст. 14.1 и 14.2
ФЗ «О защите конкуренции» и ст. 5 ФЗ «О рекламе». Общие статьи (`direction: null`)
ведут призыв на `/` или `/register`.

## Загрузка в БД

`scripts/import_articles.py` валидирует все файлы и не начинает загрузку при замечаниях,
затем для каждой статьи создаёт или обновляет запись по `slug` (kind NEWS, status PUBLISHED),
синхронизирует теги и направление, копирует обложку в `uploads/articles/covers/` и переносит
лайки, дизлайки и просмотры со старых статичных новостей по `legacy_id`. Каждая статья —
отдельная транзакция, повторный запуск безопасен.

Порядок выкладки на сервере:

```bash
docker compose up -d --build backend          # миграция 177 + новый API
docker compose exec backend python -m scripts.import_articles
docker compose up -d --build frontend         # фронт без статичных новостей
```

Пока импорт не выполнен, новый фронт отдаёт 404 на `/news/<slug>` перенесённых статей,
поэтому фронт пересобирается последним.
